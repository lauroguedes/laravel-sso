A fix release. The key set used to publish the active signing key alone, so
rotating it was a hard cutover: every ID Token signed before the swap stopped
verifying at that moment. It can now keep the key you retire next to the
active one, which is what OpenID Connect Core 1.0
[section 10.1.1](https://openid.net/specs/openid-connect-core-1_0.html#RotateSigKeys)
asks:

> The JWK Set document at the jwks_uri SHOULD retain recently decommissioned
> signing keys for a reasonable period of time to facilitate a smooth
> transition.

[Release notes on GitHub](https://github.com/lauroguedes/laravel-sso/releases/tag/v2.1.1)
·

## Added

- `SSO_PREVIOUS_PUBLIC_KEY`, or a `storage/oauth-previous-public.key` file,
  holds the public key retired by the last rotation. `/.well-known/jwks.json`
  publishes it after the active key, under its own `kid`.
- A malformed retired key is left out of the key set and reported, so an
  optional key can never take the key set down with it.

## Fixed

- ID Tokens signed before a rotation go on verifying while the retired key is
  kept. A client that meets their `kid` finds the key in the key set.
- An `id_token_hint` signed by the retired key still signs the user out
  straight away, instead of asking first.

## Upgrading

Nothing is required. To rotate a signing key, follow
[Rotating](/docs/getting-started/deployment#rotating) in the deployment guide,
which also covers what happens to access tokens during the change.
