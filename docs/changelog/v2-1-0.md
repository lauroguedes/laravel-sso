A minor release. The demonstration mode that runs the public demo is no longer
part of the application. It comes from
[lauroguedes/laravel-demo-mode](https://packagist.org/packages/lauroguedes/laravel-demo-mode),
extracted from this project. An installation that never turned the demo on sees
no difference. One that runs a demo needs the renamed settings under
[Upgrading](#upgrading).

[Release notes on GitHub](https://github.com/lauroguedes/laravel-sso/releases/tag/v2.1.0)
·
[Every change since v2.0.0](https://github.com/lauroguedes/laravel-sso/compare/v2.0.0...v2.1.0)

## Highlights

- **Demo mode is a package.** The scheduled reset, the rotating administrator
  password filled in on the sign-in page, the restrictions that stop a stranger
  abusing the server, and the notice that the data is temporary all come from
  `lauroguedes/laravel-demo-mode`, configured in `config/demo.php`.

## Added

- `php artisan demo:doctor` audits the demo configuration and exits non-zero on
  anything that would destroy data or publish a secret.
- The demo notice is a floating bar whose wording and appearance are read from
  the environment (`DEMO_BANNER_*`), so a demo can be restyled without changing
  code.
- The reset follows a cron expression, `DEMO_RESET_SCHEDULE`, and the notice's
  countdown is derived from the same expression, so it never promises a reset
  that is not coming.

## Upgrading

Nothing is required unless this installation runs a demo. If it does:

1. Rename `SSO_DEMO_MODE` to `DEMO_MODE`.
2. Replace `SSO_DEMO_RESET_HOURS` with `DEMO_RESET_SCHEDULE`, a cron expression.
   Every six hours is `"0 */6 * * *"`.
3. Replace any call to `php artisan sso:demo-reset` with
   `php artisan demo:reset`. The package schedules the reset itself, so the
   usual `schedule:run` cron entry is all it needs.
4. Run `php artisan demo:doctor` before the first scheduled reset.
